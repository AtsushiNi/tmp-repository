# 総合演習（45分）

## 課題（30分）
架空の市場データAPIと信用リスク計測処理を対象に、次の流れを図示する。実システムの秘密情報・データは使用しない。

1. 呼び出し元がGET APIへキーと日付を送る。HTTPメソッド・パラメータ・成功/失敗時のステータスを示す。
2. FastAPI Router→Service→Repository→Valkey（必要に応じてRDB）という論理処理を示す。実案件の採用構成は未確認として明示する。
3. アプリのコンテナイメージとECSタスク定義・サービスの関係を示す。
4. GitLab CI/CDでMaven/JUnitに相当するテスト・ビルド・デプロイがどの単位で実行されるかを説明する（実案件のパイプラインは未確認）。
5. リスク計算を二経路に分ける。A: CE=max(V0,0)、PE=想定元本×掛目、与信残高=CE+PE。B: リスクファクターシナリオ→将来時価→エクスポージャー→PFE分位点。CVAはEE等を使う別目的の計算として位置付ける。

## 確認・振り返り（15分）
- PEとシミュレーションPFEの違いを説明できるか。
- ValkeyのTTLだけでRDBとの同期鮮度を保証できない理由は何か。
- PFEとCVAの計算で、どこを共有でき、どこを確認しなければならないか。
- Claude Codeが実行していないテストを「成功」と報告した場合にどう対応するか。

**採点観点**: 処理の順序、技術用語の正確さ、未確定仕様の識別、説明の根拠。
